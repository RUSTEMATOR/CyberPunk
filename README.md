# Night City Life

Telegram-бот: симулятор жизни в Найт-Сити для закрытой группы 5-10 игроков. Вся игра идёт в одной группе, у каждого игрока одно окно с кнопками. Дизайн в `docs/DESIGN.md`, план в `docs/PLAN.md`, ход работы в `docs/PROGRESS.md`.

## Что нужно

- Токен бота от @BotFather.
- Docker с compose, либо Python 3.12 или новее (без Docker).
- Ключ Anthropic API нужен рассказчику Claude (брифинги, исходы, события недели, новости, разговоры с NPC, свободный план в заказе). Без ключа игра идёт на заготовках и авторских текстах, поле `ANTHROPIC_API_KEY` можно оставить пустым.

## Запуск

1. В Telegram открыть @BotFather, команда `/newbot`, получить токен.
2. Там же `/setprivacy`, выбрать бота, `Disable`. Бот должен видеть сообщения группы, чтобы читать ввод текста и чистить чат.
3. Создать группу (лучше закрытую), добавить бота и сделать его администратором с правом «Удаление сообщений». Без этого игра работает, но мусор из чата не удаляется.
4. Скопировать `.env.example` в `.env` и заполнить:
   - `BOT_TOKEN`: токен из шага 1;
   - `ADMIN_IDS`: Telegram ID администраторов через запятую (свой ID можно узнать у @userinfobot);
   - `ANTHROPIC_API_KEY`: ключ с platform.claude.com. Пустой ключ или `LLM_ENABLED=false` выключают Claude целиком;
   - чтобы Claude заработал, нужны три вещи: ключ, `LLM_ENABLED=true` и `MONTHLY_BUDGET_USD` больше нуля. Цены `PRICE_NARRATIVE_IN/OUT`, `PRICE_FAST_IN/OUT` (за миллион токенов, готовые значения в `.env.example`) обязательны: без них расход считается нулём и лимит не сработает. При 75% бюджета админам приходит предупреждение, с 90% бот пишет заготовками до начала следующего месяца (одно сообщение админам). Расход: `/admin_budget`;
   - остальное по умолчанию подходит: `DB_PATH=data/game.db`, `TIMEZONE=Europe/Kyiv`, `MONTHLY_BUDGET_USD=100`, `LLM_ENABLED=true`; `IMAGES_DIR` (папка с картинками, по умолчанию `images`) можно добавить строкой.
5. Запустить одним из способов:
   - с Docker: `docker compose up -d --build`; логи `docker compose logs -f bot`;
   - без Docker: `bash run.sh` (создаст `.venv`, поставит зависимости, проверит контент и запустит бота; остановка Ctrl+C).
6. Проверка: написать боту `/ping`, ответ `pong`. Лог лежит в `data/bot.log`.

## Первая настройка в группе

1. Выполнить в группе `/admin_setgroup`. Бот запомнит группу как игровую: в других чатах и в личке игровые команды отвечают отказом. Если у бота нет права удаления сообщений, он предупредит об этом один раз.
2. Первый запуск без `ADMIN_IDS`: тот, кто первым выполнит `/admin_setgroup` в группе, становится администратором (бот записывает это в базу и пишет предупреждение в лог). Надёжнее сразу вписать свой ID в `ADMIN_IDS`: тогда этот путь закрыт.
3. Игроки пишут `/play`, создают персонажа и играют. Справка для игроков: `/help`.

## Админ-команды

Работают только у ID из `ADMIN_IDS` (или у того, кто занял администратора при первом `/admin_setgroup`). Ответы удаляются через минуту.

- `/admin_setgroup`: сохранить текущую группу как игровую.
- `/admin_give @игрок сумма`: выдать или забрать эдди (можно ответом на сообщение игрока: `/admin_give сумма`).
- `/admin_set @игрок поле значение`: записать целое поле живого персонажа (поля бот называет в подсказке; это тестовый инструмент).
- `/admin_tick`: запустить суточный тик реального времени сейчас (жара, войны банд, курс монеты, ночные новости).
- `/admin_year [@игрок]`: личная дата игрока (без аргумента твоя), эпоха и следующее событие хроники. Общих часов мира нет: у каждого рода своё время.
- `/admin_history`: последние 10 записей истории мира.
- `/admin_veto номер`: отменить сгенерированное событие мира в пределах `world.history_veto_hours`, его эффекты откатываются (в том числе удар по курсу Эдди-крипты).
- `/admin_kill [@ник | id] [причина]` убивает персонажа обычной смертью. `/admin_event`, `/admin_budget`: пока отвечают «не реализовано» (придут с этапом M8).

## Расписание бота (время по Киеву)

- 03:00: глобальный тик реального времени: ночные новости «Ночной эфир 54», остывание жары, войны банд, курс Эдди-крипты. Канон, эпохи и доски заказов идут по личной дате персонажа.
- 04:00: резервная копия базы (см. ниже).
- 12:00, 21:00 и воскресенье 20:00: напоминания и «Легенды недели».
- Каждые 10 минут проверка пропущенного тика: если бот был выключен в 03:00, сутки тика будут догнаны при следующем запуске.

## Как добавить события

События, враги, импланты, фиксеры и всё остальное лежат в `content/*.yaml`; числа баланса в `content/balance.yaml`. Правила и поля каждого файла описаны в `docs/CONTENT_GUIDE.md`, допустимые ключи в `docs/CONTENT_KEYS.md`.

1. Открыть `content/events.yaml` (или `events_life.yaml`, `events_paths.yaml`, `events_chrome.yaml`, `events_maxtac.yaml`) и добавить запись по образцу: `id`, `title`, `category`, `weight`, `conditions`, `text`, `choices` с `effects`. Если в событии есть насильственный выбор, нужен и ненасильственный.
2. Событие мира, которое выходит в ленту города в нужный год, добавляется в `content/timeline.yaml` (поля `year`, `week`, `announcement`, `effects`, `source_note`).
3. Проверить: `python -m app.content.loader --strict` (в Docker: `docker compose run --rm bot python -m app.content.loader --strict`). Ошибка называет файл, запись и поле.
4. Перезапустить бота: контент читается при старте (`docker compose restart bot`).

## Как добавить картинки

Картинки видны только в ленте города (новости, некрологи, киберпсихи, МаксТак, смена эпохи, канонные события). Без картинок всё работает текстом.

1. Положить файл (`.png`, `.jpg`, `.jpeg`, `.webp`, до 10 МБ) в `images/`.
2. Вписать его в `images/manifest.yaml`: `- file: имя.png` и `tags: [...]`. Какие теги ищет бот и какие картинки нужны в первую очередь, написано в `docs/IMAGES.md`. Манифест уже содержит все картинки из этого списка: достаточно положить файл с тем же именем.
3. Проверить: `python -m app.services.images` (покажет ошибки манифеста, отсутствующие файлы и файлы, которых нет в манифесте). Перезапуск не нужен, манифест перечитывается при изменении. Новый файл с тем же именем загрузится в Telegram заново.

## Резервные копии и перенос базы

Вся игра лежит в одном файле SQLite (`data/game.db`, рядом файлы `-wal` и `-shm`). Там же сохранённая группа игры и администраторы, занятые при первом запуске.

- Автоматически: каждую ночь в 04:00 бот делает копию в `data/backups/game-ГГГГММДД-ЧЧММСС.db` через встроенный в SQLite механизм резервного копирования (он безопасен, пока бот пишет в базу) и хранит 7 последних. Число копий и час задаются в `content/balance.yaml`, раздел `backup`.
- Вручную: `python -m app.services.backup` (в Docker: `docker compose exec bot python -m app.services.backup`).
- Перенос на другой компьютер:
  1. Сделать копию вручную (команда выше) или взять последнюю из `data/backups/`. Не копируйте `game.db` на ходу, если не остановили бота: часть данных может лежать в `game.db-wal`.
  2. На новом месте положить файл как `data/game.db`, скопировать `.env`, `content/` и `images/`. Файлов `game.db-wal` и `game.db-shm` на новом месте быть не должно.
  3. Запустить бота. Группа игры сохранилась в базе, `/admin_setgroup` повторять не нужно (если токен бота новый, добавьте нового бота в группу администратором).
- Восстановление из копии: остановить бота, удалить `data/game.db-wal` и `data/game.db-shm`, положить копию как `data/game.db`, запустить.
- Сменить расположение базы можно переменной `DB_PATH` (папка `backups` будет лежать рядом с ней).

## Структура

- `content/` игровой контент и баланс (YAML)
- `images/` картинки ленты и `manifest.yaml`
- `data/` база, логи, резервные копии (не в git)
- `app/engine/` чистая игровая логика
- `app/services/` сценарии игры поверх базы
- `app/narrator/` обёртка над Claude API
- `app/bot/` Telegram-обработчики, тексты, окна
- `app/scheduler/` глобальный тик и ежедневные задания
- `docs/` дизайн, план, ход работы, решения (`QUESTIONS.md`), ручные тест-кейсы (`TEST_CASES.md`)

Автотестов в проекте нет по решению владельца: проверка идёт вручную по `docs/TEST_CASES.md`.
