# Unity-клиент (запрос владельца 31.10)

Игра делится на две части:
- **Текстовая игра:** бот, сервер, база. Это скелет, вся логика и все числа. Источник правды.
- **Unity-клиент:** визуальная оболочка того, что уже происходит в тексте. Свет, физика, модели, ассеты. Своих правил нет: всё, что меняет персонажа, идёт запросом на сервер, и решает сервер.

Unity-клиент открывается внутри Mini App отдельным модулем. Перед загрузкой игрок видит предупреждение с размером. Ядро грузится один раз и кэшируется браузером, содержимое (районы, транспорт) подгружается пакетами Addressables.

Контракт с сервером тот же, что у three.js-района (`docs/PLAN_CITY3D.md`, `docs/PLAN_CITY3D_2.md`): `/api/city3d/map`, `pos`, `hit`, `escape`, `crash`, `look`, токен `city3d`, двери через `postMessage {nc:"press", screen:"city", action:"d3", arg}`. three.js-район остаётся запасным вариантом для слабых устройств.

Редактор: Unity 6000.6.7f1 на Mac владельца (`/Applications/Unity/Hub/Editor/6000.6.7f1`, модуль WebGL установлен). Встроенный конвейер рендера (Built-in), без URP: так ядро легче.

## Этап 0. Проверка на телефоне
- Пустой WebGL-клиент: земля, по кругу кубы-двери района из `/api/city3d/map`, капсулы-жители, медленная камера.
- Интерфейс поверх Unity сделан на HTML: русский текст чёткий на любом экране, шрифты не грузятся в сборку. Unity передаёт странице данные района (`NcUi`), страница рисует кнопки дверей. Тап по кубу или по кнопке → `NcPress` → дверь в боте.
- Метрики устройства: время загрузки, размер, `userAgent`, экран, кадры в секунду, память WebGL. Страница отправляет их в `POST /api/unity/metric`, сервер пишет `data/unity/metrics.jsonl`.
- Кнопка «🧪 Unity-клиент (тест)» в «Городе» видна только админам.

## Этап 1. Конвейер сборки
- Бот на Mac каждые 15 с смотрит `data/unity.request` (`services/unity_jobs.py`). Заявка `{"id", "job": "probe" | "build"}`. Команды фиксированные, произвольный код не запускается.
- `probe`: есть ли редактор, модуль WebGL, лицензия, проект. Ответ в `data/unity/probe.json`.
- `build`: если проекта нет, Unity создаёт его (`-createProject unity/NightCity3D`); исходники из `unity/src/Assets/` копируются в проект; Unity в batchmode собирает WebGL в `webapp/unity/<версия>/`, версия `uГГММДДЧЧММ`. После успеха `webapp/unity/current.json` указывает на новую версию, хранятся три последние. Лог `data/unity/build-<версия>.log`, итог `data/unity/result.json`.
- Пока идёт сборка, перезапуск бота по `restart.request` откладывается.
- Файлы `Build/` версии кэшируются надолго (путь с версией), `index.html` и `current.json` без кэша.
- Сжатие Gzip с распаковкой в браузере (`decompressionFallback`): заголовки `Content-Encoding` не нужны, Cloudflare не мешает.

## Этап 2. Перенос района
- Тот же район, что в three.js: дома по сетке и стилю района, двери, жители, машина, другие игроки. Контракт API без изменений.

## Этап 3. Addressables
- Районы, транспорт и люди отдельными пакетами на сервере, подгрузка при поездке, кэш браузера.

## Этап 4. Чего нет в three.js
- Физика машин, свет и тени, анимации людей, ассеты из Blender и магазина.

## Сделано (31.10)
Этапы 0 и 1 на живом боте. Живая версия в `webapp/unity/current.json`, сборка около 40 секунд, клиент весит 5,0 МБ: код движка 4,2 МБ, данные 1 МБ.
- Проверено в Chromium с экраном iPhone 13 на заглушке сервера: предупреждение с размером, загрузка, район по `/api/city3d/map`, тап по дому и выбор из списка, «Войти» закрывает рамку и нажимает `city:d3:<дверь>` в боте, метрики `start`, `loaded`, `ready`.
- Не проверено: настоящий iPhone и Android в Telegram. Это главный вопрос этапа 0, ответ придёт в `data/unity/metrics.jsonl` после первых запусков.

Что выяснилось по ходу:
- Unity вырезает физику, если в сцене нет ни одного коллайдера, а дома создаются кодом. В сцене лежит выключенный объект с коллайдерами, плюс `link.xml`.
- Инкрементальная сборка однажды оставила старый C# в wasm. Перед каждой сборкой стираются `Library/Bee`, `ScriptAssemblies`, `PlayerDataCache`, `Il2cppBuildCache`. Сборка с нуля всё равно занимает меньше минуты.
- Выкатка файлов на мак: повторная отправка из той же папки выкладки берёт старую копию файла. Каждая выкатка идёт из новой папки, md5 на маке проверяется сразу.
- Первый запуск на iPhone 16 Pro Max (iOS 18.7, Telegram) упал с «both async and sync fetching of the wasm failed». Причина в nginx: большие ответы обрывались на 200 КБ – 1,4 МБ, файлы меньше мегабайта приходили целиком. В `deploy/nginx/nightcity.conf` добавлено `proxy_max_temp_file_size 0`, теперь nginx не пишет ответ во временный файл и отдаёт потоком. После этого 4,2 МБ приходят целиком. Параллельно в сборке выключен режим WebAssembly 2023, а страница при сбое сама проверяет движок (`stage: probe` в метриках).
- iPhone 16 Pro Max после правки nginx: загрузка 0,9 с, 60 кадров в секунду (сборка u2610310236).
- Клиент только горизонтальный (просьба владельца 31.10). Если окно вертикальное, вся сцена страницы поворачивается на 90° по часовой стрелке, игрок поворачивает телефон набок. Размер буфера Unity страница задаёт сама (`matchWebGLToCanvasSize: false`): у повёрнутого холста `getBoundingClientRect` даёт вертикальные размеры, и Unity растягивал картинку. Тап пересчитывается в координаты сцены. Панель дверей справа, при выборе двери камера поднимается и сдвигает дом влево.

## Вид от первого лица (31.10, просьба владельца «собери решение для игры от первого лица»)
- `NcCity.cs` заменил `NcProbe.cs` (файл оставлен пустым). Город по сиду района: 4×4 квартала по 22 м, улицы 11 м, дома со светящимися окнами (одна текстура 16×16, у каждого дома свой масштаб), неоновые края крыш, тротуары, фонари на перекрёстках, разметка. Цвета из `theme` района.
- Двери из `/api/city3d/map` раскладываются по фасадам, выходящим на улицы, по одной на фасад, пока есть свободные. У двери проём, неоновая рамка цвета по типу места и вывеска (название показывает страница). Жители (`npcs`, до 60) ходят у своей двери (`door`).
- Игрок: `CharacterController` (сквозь дома не пройти), глаза на 1,65 м, шаг 4,2 м/с, бег 8,5 м/с, обзор ±75°.
- Ввод собирает страница, Unity читает его раз в кадр через `NcAxis` (0, 1 движение, 2, 3 сдвиг обзора в пикселях, 4 бег). На телефоне слева джойстик, появляется под пальцем; справа обзор пальцем; кнопка «Бег». На компьютере WASD или стрелки, мышь с зажатой кнопкой, Shift бег, E или Enter войти.
- Рядом с дверью (до 3 м, перед игроком) карточка «<место> · Войти», рядом с жителем «Подойти» (`n.<id>`). Нажатие отправляет `city:d3:<id>`, как в three.js-районе.
- «Все двери» ставит игрока перед выбранной дверью.
- Статичный город склеивается `StaticBatchingUtility.Combine`, мелкие светящиеся детали без теней, жители отдельно. В сцене `CharacterController` держится от вырезания тем же объектом с коллайдерами. Материал `Neon.mat` с `_EMISSION` хранит нужный вариант шейдера.
- Проверено в Chromium (iPhone 13 горизонтально и вертикально с поворотом): ходьба, упор в дом, обзор мышью, джойстик касанием, перемещение к двери, карточка, нажатие `city:d3:p.market` уходит в приложение. На телефоне не проверено.
- Blender 5.2.3 поставлен ботом через Homebrew (`unity_jobs` задача `blender_install`), для будущих моделей.
